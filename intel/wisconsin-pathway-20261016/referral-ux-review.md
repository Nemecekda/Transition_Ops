## Post-build reviewer checklist

- [ ] **National visitor:** Resources entry is easy to find; national is the default. Every selected need has a useful national action or clearly named official locator, with no Wisconsin-only fallback or empty result. The current national next step remains visible and unchanged.
- [ ] **Planning a Wisconsin return:** Choosing Wisconsin signals interest only. A member can use work, education or moving help before arrival; no residence/entry-of-service fact is inferred. DOR/WDVA decide the relevant rules. No request for a transition date merely to browse.
- [ ] **Drilling Wisconsin Guard:** Continued service does not produce separation-only instructions. Explicit Wisconsin Guard selection may prioritize the separate Guard tuition route; the existing combined Guard/Reserve profile cannot be upgraded to Wisconsin Guard. General Wisconsin GI Bill remains a different program with its separate agency/school determinations.
- [ ] **Federal Reserve / return from orders:** Reservist selection does not prioritize the Wisconsin Guard tuition grant as an entitlement. Employer-return and healthcare routes are available with verified official sources and without newly invented USERRA/TAMP dates or qualifying assumptions. Leaving orders is not presented as leaving service.
- [ ] **Family member:** Family support uses the verified DMA/service-family route. VORP is not framed as a general family-treatment entitlement; VHRP's no-spouse/child residence limitation appears beside its action. No benefit is inferred from having a military-connected household.
- [ ] **One useful next action:** Each chosen task has a matching primary action, a named office/tool and relevant caveat. Other official routes are optional detail. `Moving` is not silently `homeless`; `health and family` is not silently `mental-health crisis`. Do not force medical or financial hardship disclosure to reach routine help.
- [ ] **Low cognitive load:** Existing service profile supplies optional context; the new flow does not require a second profile. Six need groups plus a neutral starting choice fit clearly on mobile; no second large navigation or directory is copied into the page. Labels describe outcomes, and external links say they leave the app/open a new tab.
- [ ] **Eligibility and trace:** Every rendered factual sentence maps to a final confirmed record and exact A2 scope. Program names, deciding agency, caveat and source date are available. Avoid `you qualify`, `you get`, universal free/funded claims or `all Wisconsin benefits`. Remaining program inventory stays an explicit evidence backlog.
- [ ] **Continuation:** Adding a step uses the existing review/snapshot/replace transaction. An active career/Resume/document draft stays intact. Switching state/task while a proposal is open clears only that proposal, not saved work. Cancel restores meaningful focus.
- [ ] **Navigation:** Fixed URL/history IDs only; state/task/situation survive reload and native Back/Forward. Malformed/duplicate/unknown IDs safely fall back to national help. Documents returns to the same state task; healthcare, career and old Wisconsin work-cost guide return controls restore correct heading/focus. Unrelated navigation does not retain a stale return banner.
- [ ] **Plan resumption:** A saved official referral action opens its matching state/need without inventing a more-specific service status. It can be completed/updated through the existing support loop. Editing an action's text must not cause an unrelated route to be guessed.
- [ ] **Access, visuals and costs:** 320/375 CSS-pixel views and both themes retain clear text, 44px targets and no ordinary horizontal scroll. Native keyboard operation and live status messages work. No new storage key, geolocation, network/AI request, member-content transmission or spend occurs when choosing context.
- [ ] **Evidence limits:** Synthetic flow success is recorded as local observed behavior. It does not establish real-member comprehension, retention, benefit receipt, manual assistive-technology acceptance or production correctness.

Claude's strongest objection remains useful: the state supplement should help the member do their next task, not become another prominent section competing with the whole app. The root design's Resources entry with optional context is a reasonable bounded test of that concern.
